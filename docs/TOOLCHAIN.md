invents its own. Three identities (never conflate them):

1. **Source toolchain revision** (compiler+executor source):
   `epi13/mncs-language`

2. **Executor release:** `toolchain/mncs-executor-066897e`
   (`mncs-executor-linux-x86_64`), published from `mncs-harness`. Signal
   consumes the family's pinned distribution.
3. **Executor digest:**
   `sha256:4387bae352b68020a83edbbb312794522a76c9f618cc7548a8f68384c63ecb40`
   (verified before use by `scripts/fetch_mncs_executor.py`).

## Executor resolution order

1. `MNCS_EXECUTOR` environment variable.
2. `mncs-executor` on `PATH`.
3. Sibling `mncs-language` checkout builds (`release`, then `debug`).
4. Otherwise fail closed pointing at `scripts/fetch_mncs_executor.py`.

## Library resolution

Two paths with different import power (see SIG-PRESS-001):

- `mncs test` resolves `use` through `MNCS_LIBRARY_PATH`: repo root,
  `mncs-math/src`, `mncs-numerics/src`, `mncs-test/native`, language
  library (overridable via `MNCS_MATH_SRC`, `MNCS_NUMERICS_SRC`,
  `MNCS_TEST_NATIVE`, `MNCS_LANGUAGE_LIBRARY`).
- `mncs experiment run` resolves `use` relative to the importing file
  only: kernels import sibling `mncs.signal.*` modules plus bare
  intrinsics (`sin`, `cos`). No cross-repo imports on this path.

## Oracle provenance

Corpora are generated by `scripts/build_signal_corpora.py` from numpy
`2.4.2` (independent DFT/FFT/filter/window implementations). Floats are
frozen as exact bit patterns; libm-dependent values assert through
in-MNCS tolerance windows so corpus expectations stay exact.
